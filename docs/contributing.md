# Contributing

## Repository layout

| Path | What it is |
|---|---|
| `src/it.wayexperience.unity.git-waypoint.api` | Git client library (`Api/`), no UI. Also vendors `com.unity.editor.tasks`, the native file watcher (`sfw/`) and `Mono.Posix`. |
| `src/it.wayexperience.unity.git-waypoint.ui` | Editor UI (`Editor/`). The main window is `Editor/UI/GitWaypoint/GitWaypointWindow.cs` (UI Toolkit). |
| `src/it.wayexperience.unity.git-waypoint` | Metadata of the combined package. |
| `tests/` | NUnit unit and integration tests inherited from upstream. |
| `release.sh` | One-command release (see below). |

The C# namespace is still `Unity.VersionControl.Git`, inherited from upstream.

Users install the **`upm`** branch: a flat package generated by `release.sh`
(`ui/Editor/` → `Editor/`, `api/Api/` → `Api/`). Never edit `upm` by hand.

## Dev loop

Work in a Unity project (Unity 6 recommended) where the package is **embedded**,
i.e. a folder inside the project's `Packages/` made of symlinks to this repo:

```
<project>/Packages/it.wayexperience.unity.git-waypoint/
  package.json            (copy of the upm one)
  Editor -> <repo>/src/it.wayexperience.unity.git-waypoint.ui/Editor
  Shim   -> <repo>/src/it.wayexperience.unity.git-waypoint.ui/Shim
  Api, Localization, Mono.Posix, sfw -> <repo>/src/it.wayexperience.unity.git-waypoint.api/…
  (plus the matching .meta symlinks)
```

Don't reference the sources with `file:` from outside the project: Unity doesn't
watch files outside the project, so it won't recompile on focus and you'll be
testing stale code. With the embedded folder, save and focus Unity to recompile.

Remove the `#upm` dependency from `manifest.json` while the embedded copy is
there: the two share asmdef GUIDs and can't coexist. Add the embedded folder to
the test project's `.gitignore`, otherwise **Discard all** (`git clean -fd`) wipes it.

## Compile check

The command-line build (`build.sh`, `GitWaypoint.sln`) comes from upstream and is
not part of our workflow. The reference compile is Unity in batchmode, on a
throwaway project that references the two packages with `file:` (fine here,
batchmode always starts fresh):

```sh
Unity -batchmode -quit -nographics -projectPath <compilecheck-project> -logFile /tmp/compile.log
grep -E 'error CS|warning CS|UAC' /tmp/compile.log
```

Runtime errors end up in `<project>/Logs/Editor.log`.

Things the Unity Mono runtime doesn't have: `Process.Kill(bool entireProcessTree)`,
for one. Code must also compile on Unity 6.5 (`#if UNITY_6000_5_OR_NEWER` where
the EntityId API differs).

## Style

- PascalCase for types, public members and constants; camelCase for private
  members, parameters and locals.
- No space before `()` in calls and definitions; a space before `()` after `if`,
  `for`, `while`; a space before `{`.
- English everywhere: code, comments, UI text, commit messages, changelog.

## Releasing

```sh
./release.sh <version> "<changelog note>"
```

It bumps the three `package.json` and `ApplicationInfo.FallbackVersion`, adds a
`CHANGELOG.md` entry, commits and pushes `main`, mirrors the sources to `upm`,
then tags `v<version>` and creates the GitHub Release (needs `gh`).

- Only `src/` and `CHANGELOG.md` go into the release commit: commit anything else first.
- The note can have several lines; write one English bullet per change.
- To update a project already using `#upm`: Package Manager ▸ Git Waypoint ▸ Update
  (or remove the package's entry from `packages-lock.json`). Don't edit that file by hand otherwise.
